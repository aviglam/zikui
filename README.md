# זיכוי חלקים – אפליקציה לטלפון

סריקת חלקים לכלוב ושליחת הרשימה למחסן כ-PDF. האפליקציה היא PWA: מותקנת מהדפדפן ועובדת גם בלי קליטה.
הנתונים נשמרים ב-Google Sheet הקיים, ושם יוצאים גם המייל וה-PDF. אפשר להמשיך לעבוד גם מהגיליון, על אותם נתונים.

```
apps-script/Code.gs            ← מחליף את הסקריפט בגיליון (כולל כל ההתנהגות הקיימת + API לאפליקציה)
apps-script/Config.gs          ← נמענים ושם טכנאי (לא עולה ל-GitHub)
apps-script/Config.example.gs  ← תבנית ל-Config.gs
docs/                          ← האפליקציה (מתפרסמת ב-GitHub Pages)
test/                          ← בדיקות לקוד השרת + שרת מקומי
```

## התקנה – פעם אחת

### 1. הסקריפט בגיליון
1. בגיליון: **Extensions → Apps Script**.
2. מחליפים את כל התוכן של `Code.gs` בקובץ `apps-script/Code.gs`.
3. מוסיפים קובץ חדש (**+ → Script**) בשם `Config` ומדביקים את `apps-script/Config.gs`.
4. בוחרים בפונקציה `setupApi` ולוחצים **Run**, ומאשרים הרשאות.
5. **Execution log** → מעתיקים את "מפתח גישה לאפליקציה".

`setupApi` מוסיפה עמודה מוסתרת F (מזהה פריט), ולא מוחקת נתונים.

### 2. פרסום ה-API
1. **Deploy → New deployment → ⚙ → Web app**.
2. **Execute as: Me** · **Who has access: Anyone**.
3. **Deploy** → מעתיקים את ה-URL שנגמר ב-`/exec`.

"Anyone" אומר שהכתובת ציבורית, אבל כל בקשה בלי המפתח נדחית.

> ⚠ אחרי כל שינוי בקוד צריך: **Deploy → Manage deployments → ✏ → Version: New version → Deploy**.
> בלי זה הכתובת ממשיכה להריץ את הגרסה הקודמת. הכתובת עצמה לא משתנה.

### 3. GitHub Pages
1. יוצרים ריפו ציבורי ב-GitHub ומעלים את התיקייה. `Config.gs` לא עולה (מוגדר ב-`.gitignore`).
2. **Settings → Pages → Source: Deploy from a branch → `main` / `/docs`**.
3. אחרי כדקה האפליקציה זמינה בכתובת `https://<שם-משתמש>.github.io/<ריפו>/`.

### 4. בטלפון
1. פותחים את הכתובת ב-Chrome (באייפון: Safari) → **התקן אפליקציה / הוסף למסך הבית**.
2. ⚙ → מדביקים את כתובת ה-Web App ואת המפתח → **בדוק חיבור** → **שמור**.
3. ברירת המחדל היא **מצב בדיקה**. כדאי לשלוח משלוח בדיקה אחד מלא לפני שעוברים ל"אמיתי".

כדי לנסות את הממשק בלי חיבור לגיליון, כותבים `demo` בשדה הכתובת. במצב הזה לא נשלח שום מייל.

## שימוש

**סריקה** – הסורק שולח Enter אחרי כל ברקוד, והסמן עובר לשדה הבא. כל ברקוד מזוהה לפי התבנית שלו ונכנס לשדה הנכון, גם אם הסדר התבלבל:

| שדה | תבנית | דוגמה |
|---|---|---|
| Case ID | 10 ספרות | `5166539780` |
| Part Number | 5–7 תווים, מקף, 3 תווים | `N36076-001` |
| RMA | 14–18 ספרות ואות | `0619940586010200B` |

ברקוד שלא מתאים לאף תבנית נכנס לשדה שבו נמצא הסמן, ומוצגת אזהרה. כשכל שלושת השדות מלאים, בוחרים מצב: **Defective** (מקש 1) או **Unused** (מקש 2). הפריט נוסף לרשימה והסמן חוזר ל-Case ID.

- ברקוד שנסרק לפני שנבחר מצב נחסם, ומוצגת אזהרה. הוא לא נכנס בטעות כ"מקש 1".
- אם המקלדת בטלפון בעברית, התווים מומרים אוטומטית לאנגלית ומוצגת אזהרה.
- 📷 ליד כל שדה פותח סריקה במצלמה, כגיבוי לסורק.
- הקשה על פריט ברשימה פותחת עריכה או מחיקה.
- פריט זהה לגמרי (Case+PN+RMA) מסומן בצהוב. זו אזהרה בלבד, והיא לא חוסמת שליחה.

**בלי קליטה** – אפשר לסרוק ולהוסיף כרגיל. הפריטים מסומנים "⏳ לא סונכרן" ועולים לגיליון כשחוזרת קליטה.
שליחה, תצוגה מקדימה, היסטוריה והחלפת מצב דורשות חיבור.

**שליחה** – זהה להתנהגות בגיליון:
1. **שלח משלוח** מסנכרן את כל הפריטים ומציג ספירה: מצב, נמענים, כמה Defective/Unused ואזהרת כפולים.
2. סופרים את הכלוב ולוחצים **הכלוב תואם – שלח**.
   - אם הרשימה השתנתה בינתיים (גם מהגיליון), המשלוח לא נשלח ומוצגת ספירה מחודשת.
   - האישור פג אחרי 15 דקות.
   - החלפת מצב עבודה מבטלת שליחה פתוחה.
3. סדר הפעולות: מייל קודם. רק אם הוא הצליח: שמירת ה-PDF ב-Drive, העברה להיסטוריה, ניקוי הרשימה וקידום המונה. אם המייל נכשל, לא נמחק כלום.
4. אחרי השליחה, **שתף PDF…** פותח את תפריט השיתוף של הטלפון (וואטסאפ וכד').

## אבטחה
המפתח הוא ההגנה היחידה. מי שיש לו גם הכתובת וגם המפתח יכול לשלוח מיילים מהחשבון שלך.
אם המפתח דלף: מריצים `rotateApiKey` ב-Apps Script ומזינים את המפתח החדש באפליקציה.

## פיתוח
```
node --test test/gs.test.js   # בדיקות לקוד השרת עם סביבת Apps Script מדומה
python test/serve.py          # http://localhost:8765
```
אחרי שינוי ב-`sw.js` מעלים את `CACHE` (מספר הגרסה) כדי שהטלפון יוריד את הגרסה החדשה. שינוי בקבצים האחרים נכנס בפתיחה השנייה של האפליקציה.
